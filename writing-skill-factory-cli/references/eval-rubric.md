# 评估维度与评分标准

## 评估分类

评估分为两大类：

1. **结构维度** — 评估 skill 本身的工程质量
2. **效果维度** — 评估 skill 生成内容的实际效果

## 结构维度

| 子维度 | 权重 | 评分标准 | 检查方式 |
|--------|------|---------|---------|
| 文件结构完整性 | 20% | 必需文件全部存在（SKILL.md + 5 个 references + 4 个 assets + evals） | 文件存在性检查 |
| Rules 分层清晰度 | 20% | L1/L2/L3 规则分类明确，confidence 状态正确 | 解析 style-memory.json |
| Supporting files 职责明确性 | 20% | 每个文件职责单一，无重复堆叠 | 人工/半自动检查 |
| Eval 覆盖度 | 20% | 至少覆盖素材成稿、风格迁移、边界判断三类 | 解析 evals.json |
| Git 版本管理规范性 | 20% | commit 历史清晰，tag 规范，release-index 同步 | git log + 文件检查 |

### 结构维度评分表

| 得分 | 描述 |
|------|------|
| 5 (优秀) | 完全满足标准，有额外加分项 |
| 4 (良好) | 满足标准，小瑕疵可忽略 |
| 3 (合格) | 基本满足，有明显改进空间 |
| 2 (不合格) | 缺少重要文件或结构混乱 |
| 1 (差) | 严重缺失，无法使用 |

## 效果维度

| 子维度 | 权重 | 评分标准 | 评估方式 |
|--------|------|---------|---------|
| 风格贴合度 | 20% | 输出与目标作者风格的一致性 | 与样文对比 + 人工判断 |
| 活人感 | 15% | 是否有真人写作的温度、节奏与个性 | 人工判断 |
| 长文推进力 | 15% | 文章结构是否层层推进、逻辑连贯 | 逐段检查论证链 |
| AI 味减少程度 | 15% | 是否消除了常见 AI 生成痕迹 | 与 baseline 对比 |
| 作者边界控制 | 15% | 是否遵守 AI/人边界，不伪造经历 | 边界案例测试 |
| 选题判断准确性 | 10% | 对劣质选题是否有拦截能力 | 边界判断类 eval |
| 信息充足性处理 | 10% | 信息不足时是否追问而非编造 | 边界判断类 eval |

### 效果维度评分表

| 得分 | 描述 |
|------|------|
| 5 (优秀) | 难以区分于真人写作 |
| 4 (良好) | 整体自然，偶有小瑕疵 |
| 3 (合格) | 可用，但有明显改进空间 |
| 2 (不合格) | AI 味重或边界控制失效 |
| 1 (差) | 严重偏离目标风格或编造事实 |

## 总分计算

```
总分 = 结构维度平均分 * 0.3 + 效果维度平均分 * 0.7
```

## 评估流程

1. **Baseline 生成**：使用无 skill 状态的 Claude 生成对照稿
2. **Candidate 生成**：使用 candidate skill 生成测试稿
3. **结构评估**：自动检查文件结构、rules 分层、eval 覆盖度
4. **效果评估**：对比 baseline vs candidate，逐项打分
5. **报告生成**：输出 `reports/eval-summary.md`，包含：
   - 各维度得分与对比
   - 具体案例（好/坏片段）
   - 改进建议
   - 总分与推荐决策

## 用户裁决

- 自动评估分数仅供参考
- **必须由用户确认"更好"后才允许 publish**
- 用户可 override 自动评估的推荐
